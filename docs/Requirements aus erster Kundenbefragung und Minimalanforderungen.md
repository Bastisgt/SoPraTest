## Dataset
- **DS-01** `MUST` The software provides example animations, including at least one confirmed reference animation
- **DS-02** `SHOULD` Example animations can be from any field (industrial context preferred)
- **DS-03** `MUST` The dataset contains: correct animation (OK), display error (NOK), movement/timing error (NOK), optional edge case (OK)
- **DS-04** `MUST` At least two animation-related error types (e.g. delayed pop-up, wrong highlight timing, missing elements, flickering)
- **DS-05** `MUST` Each test case has an ID, an error type, an expected result (OK/NOK) and a linked reference
- **DS-06** `MUST` Faulty test cases are generated by a script or a documented procedure (reproducible)
- **DS-07** `MUST` The user can upload clips and set error type and expected result

## Models
- **MOD-01** `MUST` At least 2 VLMs
- **MOD-02** `MUST` The user can choose a model
- **MOD-03** `SHOULD` Models of different sizes, at least one lightweight (keep resource usage in mind)
- **MOD-04** `MUST` Models can have different configurations, each documented and justified
- **MOD-05** `COULD` The user can set model parameters
- **MOD-06** `MUST` Model setup / API integration is documented

## Pre-Processing
- **PRE-01** `MUST` Pre-processing is always applied (format, scaling, frame reduction, filters)
- **PRE-02** `MUST` Pre-processing is well documented (what, when, why)
- **PRE-03** `SHOULD` Pre-processing is transparent for the user (which frames were sent)

## Evaluation
- **EVAL-01** `MUST` The user can run an evaluation on a set of test cases with a chosen model and prompt
- **EVAL-02** `MUST` The model result is mapped to OK / NOK
- **EVAL-03** `MUST` Per test case the software stores: ID, expected result, model result, reasoning, runtime, tokens
- **EVAL-04** `MUST` Each run stores model, prompt version and settings (reproducibility)
- **EVAL-05** `MUST` The software does not fix deviations, it only reports them

## Metrics & Comparison
- **MET-01** `MUST` Accuracy, Precision, Recall per model (NOK = positive class)
- **MET-02** `MUST` TP / FP / TN / FN are shown
- **MET-03** `MUST` Average runtime and token usage per test case (+ estimated cost)
- **MET-04** `MUST` The user can compare different VLMs
- **MET-05** `MUST` Baseline prompt vs. improved prompt is compared
- **MET-06** `SHOULD` Past runs remain accessible
- **MET-07** `MUST` Results exportable as CSV/JSON

## Later Version
- **LAT-01** `COULD` Mark detected deviations (timestamp / highlighting)

## Non-Functional
- **NFR-01** `MUST` Deployed via Dokploy, accessible through a browser
- **NFR-02** `MUST` API keys are not stored in the repository
- **NFR-03** `MUST` REST API is tested and documented
- **NFR-04** `SHOULD` Frontend is simple, focus is on backend and results

## Deliverables
- **DEL-01** `MUST` Recommendation: preferred model, limitations, next steps
- **DEL-02** `MUST` Documentation of process and key decisions
